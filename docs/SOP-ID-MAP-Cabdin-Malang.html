STANDAR OPERASIONAL PROSEDUR

Sistem Informasi Geografis Integrated Database — Map of Conservation Area (ID MAP) Cabdin KP Malang

1. Pendahuluan

ID MAP (Integrated Database — Map of Conservation Area) Cabdin KP Malang adalah sistem informasi geografis berbasis web yang dikembangkan oleh Cabang Dinas Kelautan dan Perikanan (Cabdin KP) Malang untuk mendukung pengelolaan data kawasan konservasi perairan, pesisir, dan pulau-pulau kecil (KP3K) di wilayah Kabupaten Malang.

Sistem ini dibangun menggunakan teknologi React (TypeScript), Vite, Tailwind CSS, dan Convex sebagai backend, serta menyediakan peta interaktif berbasis Leaflet. ID MAP memungkinkan pengelolaan data survei lapangan secara offline-first dengan sinkronisasi otomatis saat perangkat terhubung ke internet.

Terdapat tiga jenis pengguna (role) dalam sistem ini, yaitu:

  1. Pengunjung (Publik) — dapat mengakses peta publik dan informasi umum tanpa login.
  2. Admin — memiliki akses penuh untuk input data, kelola data, dan generate laporan.
  3. Verifikator — bertugas memverifikasi dan memvalidasi data survei yang masuk.

2. Tujuan

SOP ini bertujuan untuk:

  1. Memberikan panduan yang jelas dan terstruktur bagi seluruh pengguna ID MAP Cabdin KP Malang.
  2. Menstandarisasi alur pengelolaan data survei mulai dari input, verifikasi, hingga publikasi.
  3. Memastikan kualitas dan keakuratan data kawasan konservasi yang tersimpan dalam sistem.
  4. Menjaga konsistensi penggunaan fitur oleh setiap role pengguna.
  5. Memudahkan pelatihan dan orientasi pengguna baru.

3. Ruang Lingkup

SOP ini mencakup seluruh aktivitas penggunaan sistem ID MAP Cabdin KP Malang, meliputi:

  1. Manajemen Akun dan Autentikasi — Login, role-based access control.
  2. Eksplorasi Peta Publik — Fitur peta interaktif untuk masyarakat umum.
  3. Input Data Lapangan — Pengisian formulir survei (vegetasi, potensi, penyu) oleh admin.
  4. Verifikasi Data — Proses validasi dan approval data oleh verifikator.
  5. Monitoring Dashboard — Pantauan KPI dan statistik.
  6. Laporan dan Ekspor Data — Generate laporan, CSV, dan GeoJSON.

5. Prosedur untuk Pengunjung (Publik)

Karakteristik Pengunjung: Tidak perlu login. Dapat mengakses halaman publik dan peta interaktif.

5.1. Mengakses Halaman Utama

1
Buka browser dan akses URL aplikasi ID MAP Cabdin KP Malang.
2
Sistem akan menampilkan Landing Page yang berisi informasi umum tentang kawasan konservasi di Malang, statistik, dan fitur unggulan.
3
Gulir halaman untuk melihat ringkasan data, lokasi, dan informasi kontak.
Fitur yang tersedia di Landing Page: statistik KPI (luas kawasan, jumlah titik monitoring, dll), galeri, dan navigasi ke halaman peta publik.

5.2. Melihat Peta Publik

1
Klik tombol "Peta Publik" atau "Jelajahi Peta" pada Landing Page atau navigasi.
2
Sistem menampilkan Peta Interaktif Publik berbasis Leaflet dengan berbagai layer peta:
2a
Layer Kawasan Konservasi (KKPD, MHI Mangrove, dll)
2b
Layer Pemanfaatan Ruang Laut
2c
Layer Titik Monitoring dan Survei (dengan status verifikasi)
3
Navigasi peta: gunakan scroll untuk zoom, drag untuk geser peta.
4
Klik marker atau area pada peta untuk melihat informasi detail lokasi.
5
Gunakan panel samping untuk melihat daftar lokasi dan kategori.

5.3. Mengunduh Data Publik

1
Pada halaman Peta Publik, klik tombol Download.
2
Pilih format unduhan yang tersedia: GeoJSON (data geospasial) atau CSV (data tabular).
3
Sistem akan mengunduh file data publik yang dapat digunakan secara terbuka.

5.4. Registrasi / Login (Opsional)

1
Jika pengunjung ingin mengakses fitur lebih lanjut, klik tombol Login atau Daftar.
2
Masukkan email dan password, atau gunakan akun demo yang disediakan.
3
Setelah login, pengguna akan diarahkan ke halaman Dashboard (jika memiliki role Admin/Verifikator).
Catatan: Akun demo hanya untuk tujuan demonstrasi. Data yang dimasukkan menggunakan akun demo bersifat sementara.

6. Prosedur untuk Admin

Karakteristik Admin: Memiliki akses penuh ke seluruh fitur sistem. Dapat melakukan input data, kelola data, melihat dashboard, mencetak laporan, dan mengelola peta interaktif.

6.1. Login dan Dashboard

1
Buka halaman Login dan masukkan kredensial akun Admin.
2
Setelah login, sistem menampilkan Dashboard utama.
3
Dashboard menyajikan KPI (Key Performance Indicators):
3a
Total luas kawasan konservasi (ha)
3b
Jumlah titik monitoring
3c
Jumlah survei yang telah dilakukan
3d
Status verifikasi data (pending / approved / rejected)
3e
Data Pokmaswas aktif

6.2. Input Data Lapangan (Survei)

Admin melakukan input data hasil survei lapangan melalui halaman Input Lapangan. Formulir survei mencakup tiga jenis data utama:

6.2.1. Monitoring Vegetasi

1
Pilih tujuan survei: Monitoring Vegetasi.
2
Isi data lokasi: provinsi, kabupaten/kota, kecamatan, desa, titik koordinat (latitude/longitude).
3
Masukkan data vegetasi: jenis vegetasi, jumlah, tinggi rata-rata (m), diameter batang (cm).
4
Ambil foto lokasi dengan fitur geotagging (koordinat otomatis dari foto).
5
Lengkapi data pendukung: kondisi lingkungan, ancaman yang teridentifikasi.

6.2.2. Data Potensi

1
Pilih tujuan survei: Potensi.
2
Isi data lokasi dan titik koordinat.
3
Masukkan informasi potensi: jenis potensi, perkiraan luas, volume, dan catatan lapangan.
4
Dokumentasikan dengan foto dan catatan GPS.

6.2.3. Data Penyu

1
Pilih tujuan survei: Penyu.
2
Isi data lokasi dan titik koordinat pantai pendaratan.
3
Masukkan data spesies penyu: jenis penyu, jumlah sarang, jumlah telur, jumlah jejak, panjang karapas.
4
Data sarang dapat dimasukkan manual atau melalui GPS (multi-point).
5
Upload foto dokumentasi.

6.3. Pengelolaan Data Survei

1
Setelah submit, data tersimpan di local storage (offline-first) dan antrean sinkronisasi.
2
Saat perangkat terhubung internet, data otomatis disinkronkan ke server Convex.
3
Admin dapat melihat riwayat survei yang pernah dimasukkan melalui halaman Input Lapangan (tab Riwayat).
4
Data yang sudah pernah diverifikasi tidak dapat diubah. Hubungi verifikator untuk koreksi.
Offline Mode: ID MAP mendukung input data secara offline. Data akan tersimpan di browser lokal dan secara otomatis dikirim ke server saat koneksi internet tersedia. Antrean sinkronisasi dapat dipantau melalui indikator di halaman Input Lapangan.

6.4. Cetak Berita Acara (BA)

1
Setelah submit survei, klik tombol Cetak BA.
2
Sistem akan membuka jendela cetak browser dengan format Berita Acara resmi.
3
Dokumen BA mencakup: identitas pelaksana, data lokasi, hasil pengukuran, foto, dan tanda tangan.
4
Cetak atau simpan sebagai PDF untuk arsip.

6.5. Dashboard dan Monitoring

Admin dapat memantau seluruh aktivitas melalui Dashboard yang menampilkan:

  • Statistik real-time kawasan konservasi
  • Status verifikasi data (menunggu, disetujui, ditolak)
  • Jumlah survei per periode waktu
  • Data Pokmaswas aktif
  • Tren data dari waktu ke waktu

6.6. Peta Interaktif (Login)

1
Akses halaman Peta Interaktif (memerlukan login).
2
Fitur tambahan dibanding peta publik: menampilkan data Pokmaswas, titik survei dengan detail verifikasi.
3
Filter data berdasarkan kategori dan status verifikasi.

6.7. Laporan dan Ekspor Data

1
Buka halaman Laporan.
2
Pilih jenis laporan yang ingin di-generate: data vegetasi, data penyu, data potensi, atau ringkasan.
3
Klik tombol Cetak untuk mencetak laporan.
4
Gunakan fitur ekspor untuk mengunduh data dalam format CSV atau GeoJSON.

6.8. Kelola Data Pokmaswas

1
Buka halaman Data Pokmaswas.
2
Lihat daftar kelompok masyarakat pengawas yang terdaftar.
3
Tambah/edit data Pokmaswas melalui form yang tersedia.

7. Prosedur untuk Verifikator

Karakteristik Verifikator: Bertugas memeriksa, memvalidasi, dan menyetujui/menolak data survei yang dimasukkan oleh Admin. Memiliki akses ke Dashboard, Verifikasi Data, Peta Interaktif, dan Laporan.

7.1. Login dan Akses Halaman Verifikasi

1
Login menggunakan akun Verifikator yang telah ditentukan.
2
Dashboard menampilkan ringkasan jumlah data yang menunggu verifikasi (pending).
3
Klik menu Verifikasi Data untuk masuk ke halaman verifikasi.

7.2. Melakukan Verifikasi Data

1
Halaman Verifikasi Data menampilkan daftar seluruh data survei yang telah masuk.
2
Gunakan filter untuk menyaring data berdasarkan:
2a
Status verifikasi (Pending / Approved / Rejected)
2b
Tujuan survei (Vegetasi / Potensi / Penyu)
3
Klik salah satu data survei untuk melihat detail lengkap, termasuk:
3a
Data lokasi dan koordinat GPS
3b
Data pengukuran (vegetasi/potensi/penyu sesuai jenis survei)
3c
Dokumentasi foto
3d
Catatan ancaman yang teridentifikasi
4
Periksa kelengkapan dan keakuratan data. Verifikator dapat membuka tautan Google Maps untuk verifikasi koordinat lokasi.
5
Putuskan status verifikasi:
5a
Approved (Disetujui) — data lengkap, akurat, dan dapat dipublikasikan. Klik tombol Setuju.
5b
Rejected (Ditolak) — data tidak lengkap atau tidak akurat. Klik tombol Tolak dan berikan catatan/alasan penolakan.
6
Sistem akan menyimpan status verifikasi beserta nama verifikator dan timestamp.

7.3. Memantau Status Verifikasi

1
Dashboard menampilkan statistik verifikasi secara real-time.
2
Data yang sudah diverifikasi akan muncul di Peta Publik dan Peta Interaktif dengan badge status.
3
Data yang ditolak dapat diperbaiki oleh Admin dan diajukan kembali untuk verifikasi ulang.

7.4. Kriteria Verifikasi

7.4.1. Kelengkapan Data

  • Lokasi: provinsi, kab/kota, kecamatan, desa terisi lengkap.
  • Koordinat GPS valid (lat: -90 s.d 90, lng: -180 s.d 180).
  • Data pengukuran sesuai jenis survei (vegetasi/potensi/penyu).
  • Minimal 1 foto dokumentasi.

7.4.2. Keakuratan Data

  • Koordinat sesuai dengan lokasi survei di lapangan (diverifikasi melalui peta).
  • Data pengukuran masuk akal (contoh: tinggi vegetasi tidak negatif, diameter dalam rentang wajar).
  • Jenis spesies yang dipilih sesuai dengan klasifikasi yang tersedia di sistem.

7.4.3. Konsistensi

  • Unit kerja (Unit Kerja) terisi sesuai dengan wilayah tugas.
  • Data ancaman yang dipilih relevan dengan lokasi survei.
  • Foto dokumentasi sesuai dengan lokasi dan objek survei.

8. Alur Kerja End-to-End

Berikut adalah alur kerja lengkap dari awal (pengguna datang) hingga akhir (data terpublikasi):

1
Admin Login — Admin login ke sistem menggunakan akun yang terdaftar.
2
Admin Input Data Survei — Admin melakukan input data hasil survei lapangan (Vegetasi / Potensi / Penyu) lengkap dengan koordinat GPS, foto, dan catatan. Data disimpan di local storage (offline) dan disinkronkan ke server.
3
Admin Cetak Berita Acara — Admin mencetak BA sebagai dokumen resi hasil survei.
4
Sistem Sinkronisasi — Data secara otomatis dikirim ke server Convex. Status awal: Pending.
5
Verifikator Verifikasi Data — Verifikator membuka halaman Verifikasi Data, memeriksa detail survei, dan memutuskan: Approved atau Rejected.
6
Sistem Update Status:
→ Jika Approved: data tampil di Peta Publik & Peta Interaktif dengan badge "Terverifikasi".
→ Jika Rejected: data kembali ke Admin untuk perbaikan dengan catatan penolakan.
7
Admin Perbaikan Data (Jika Ditolak) — Admin memperbaiki data berdasarkan catatan verifikator dan mengirimkan ulang.
8
Verifikator Verifikasi Ulang — Verifikator memeriksa ulang data yang telah diperbaiki.
9
Publik Akses Data Publik — Data yang sudah Approved dapat diakses oleh publik melalui Peta Publik dan diunduh dalam format GeoJSON/CSV.
